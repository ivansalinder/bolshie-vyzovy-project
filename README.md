# ReadCheck — Веб-платформа скрининга навыков чтения

Веб-приложение для проведения скрининговых тестов навыков чтения у детей с двумя пользовательскими сценариями: **Родитель** и **Специалист**. Проект разрабатывается с учётом требований по размещению на российской инфраструктуре, сжатых сроков прототипирования (10 дней) и заделом под дальнейшую аналитику и научные исследования.

## Пользовательские сценарии

1. **Родитель**:
   - Регистрация и авторизация, выбор роли, заполнение базового профиля.
   - Добавление и управление профилями своих детей.
   - Прохождение ребёнком скрининга навыков чтения.
   - Получение общих понятных результатов и сводных статусов.

2. **Специалист**:
   - Регистрация и авторизация, выбор роли, заполнение расширенного профиля (квалификация, место работы/практики и т.д.).
   - Добавление и ведение профилей подопечных/детей.
   - Прохождение ребёнком скрининга.
   - Получение детальных метрик, показателей по навыкам, динамики и расширенных отчётов.

## Технологический стек

- **Frontend**: React, JavaScript / TypeScript, Vite, React Router, Lucide React, Recharts, React Hook Form, Zod.
- **Backend**: Python, FastAPI, Pydantic.
- **Database**: PostgreSQL.
- **Инфраструктура и инструменты**: Docker / Docker Compose, Git / GitHub, VPS на российской инфраструктуре (например, Yandex Cloud, Selectel, Timeweb Cloud), Figma.

## Архитектура

Приложение строится по клиент-серверной схеме:
- **Frontend (React)** отвечает за пользовательские интерфейсы, личные кабинеты, интерактивный экран тестирования (тексты, таймеры, ответы, сбор сырых событий прохождения) и визуализацию результатов.
- **Backend (FastAPI)** обеспечивает авторизацию и разграничение прав по ролям, работу с профилями и детьми, приём и валидацию данных тестирования, расчёт метрик и формирование отчётов для родителей и специалистов.
- **Database (PostgreSQL)** хранит пользователей, профили, карточки детей, материалы/сессии скрининга, сырые данные прохождения и рассчитанные результаты.

## Распределение зон ответственности (3 разработчика)

Чтобы у всех участников была сопоставимая нагрузка и минимум блокировок на старте:

- **Разработчик 1 (Frontend — Онбординг и личные кабинеты)**:
  - Страницы регистрации, входа и выбора роли.
  - Формы профиля родителя и расширенного профиля специалиста.
  - Личные кабинеты, управление профилями детей, история прохождений и отображение результатов/графиков.
- **Разработчик 2 (Frontend — Движок скрининга)**:
  - Экран прохождения теста ребёнком: вывод текстов, таймеры, обработка ответов и действий пользователя.
  - Формирование и отправка структурированных сырых данных прохождения на бэкенд.
- **Разработчик 3 (Backend, БД и аналитика)**:
  - Проектирование схемы PostgreSQL и настройка API на FastAPI.
  - Авторизация и проверка прав доступа для разных ролей.
  - Алгоритмы расчёта метрик чтения, логирование данных для дальнейшей аналитики и исследований, а также подготовка развёртывания через Docker.

## План работы на 10 дней (MVP)

1. **Дни 1–3**: Согласование контрактов API и структуры данных, поднятие БД и базового каркаса FastAPI, вёрстка авторизации, профилей и кабинетов.
2. **Дни 4–7**: Реализация эндпоинтов профилей/детей, сборка интерактивного экрана скрининга и отправка данных теста, базовые расчёты на бэкенде.
3. **Дни 8–10**: Интеграция отображения общих и детальных результатов, тестирование обоих сценариев, упаковка в Docker и запуск прототипа на сервере.

## Локальный запуск

> Раздел будет дополняться по мере добавления `docker-compose.yml`, инструкций по переменным окружения (`.env`) и команд запуска фронтенда и бэкенда.

1. Клонируйте репозиторий:
   ```bash
   git clone <URL_РЕПОЗИТОРИЯ>
   cd <ПАПКА_ПРОЕКТА>
   ```
2. Настройте переменные окружения для backend и frontend согласно примерам в репозитории.
3. Запустите сервисы и базу данных через Docker Compose (после добавления конфигурации в репозиторий) либо поднимите backend, PostgreSQL и frontend локально.
